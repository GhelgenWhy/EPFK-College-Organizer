# Frontend API

Сторінки завантажують дані через `src/services/api/`, без імпорту локальних моків.

| Файл | Відповідальність |
| --- | --- |
| `client.ts` | Clerk bearer token, cookies, HTTP-помилки, JSON та скасування запитів |
| `organizer.ts` | `/api/home`, `/api/calendar`, `/api/events`, `/api/schedule`; перевірка відповідей та адаптація головної сторінки |
| `moodle.ts` | `/moodle/courses`, `/moodle/assignments/:courseId`; адаптація DTO до типів UI |
| `useApiQuery.ts` | Стан завантаження, помилки, повторна спроба та ізоляція даних за сесією |
| `validation.ts` | Перевірка структури JSON на межі API |

Приклад використання на сторінці:

```tsx
const query = useApiQuery(organizerApi.getCalendar);

return (
  <>
    <ApiQueryStatus query={query} />
    {query.data && <CalendarGrid events={query.data} {...calendarProps} />}
  </>
);
```

Передавайте стабільну функцію завантаження (наприклад, метод `organizerApi`), а не нову inline-функцію на кожному рендері. Для параметризованого запиту використовуйте `useCallback`.

Хук чекає на Clerk, скасовує запит при демонтуванні або зміні сесії, приховує дані попередньої сесії та ігнорує запізнілі відповіді. `retry()` скидає попередній результат і запускає новий запит. Компоненти з локальними відмітками виконання монтуються після отримання даних; ключі localStorage містять Clerk user ID. Відмітки залишаються локальними й не означають надсилання роботи в Moodle.

## Маршрути та запуск

Vite проксіює `/api` та `/moodle` на `BACKEND_ORIGIN` (типово `http://localhost:3000`). Для production reverse proxy також має передавати обидва префікси до NestJS: шляхи запитів відносні, із cookies поточного origin.

```powershell
npm run dev
npm run build
npm run lint
```

## Moodle

Фронт завантажує дисципліни зі списку курсів, а завдання збирає за всіма курсами, максимум чотири запити одночасно. Якщо один запит завершується помилкою, сторінка показує помилку з повторною спробою замість неповного списку. Дати серіалізованих DTO перетворюються на дату й час у `Europe/Kyiv`; nullable-поля обробляються в адаптері. HTML-описи показуються як звичайний текст.

Поточні обмеження бека:

- Методи Moodle очікують cookie `moodle_token`. У наявному контролері немає маршруту входу, що викликає `getToken()` та встановлює цю cookie. Збереження логіна й пароля в профілі Clerk її не створює. Фронт передає наявні cookies, але сам отримати Moodle-сесію через поточний API не може.
- DTO повертають загальне посилання `https://moodle.org`, а не URL конкретного курсу або завдання. Фронт використовує отримане посилання.
- `getUser()` є лише методом сервісу; HTTP-маршрут для нього не опубліковано. Профіль поки використовує Clerk.

API головної, календаря, подій і розкладу наразі повертає демонстраційні дані з бека. Автоматичної підміни відповіді локальними моками на фронті немає.
